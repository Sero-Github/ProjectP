# 2. 제안 구조
## 2-1. 위치
```
Game Design Documents/
├── 35 스탯/                     ← 신규 폴더
│   ├── 📊 몬스터 스탯.md
│   ├── 📊 플레이어 스탯.md
│   ├── 📊 스킬 점수.md
│   ├── 📊 스킬 스탯.md
│   ├── 📊 속성 스탯.md
│   └── 📊 액티브 스킬 스탯.md
```
- 기존 `30 능력/📊 스탯.md`는 내용을 모두 옮긴 뒤 삭제합니다. 이 문서를 가리키던 링크는 [[#4. 링크 재설정 목록]]대로 새 문서로 바꿉니다.
- 번호 `35`는 능력(30)과 데이터(40) 사이입니다. Home의 문서 목록에 `35 스탯` 묶음을 추가합니다.

## 2-2. 수치의 소유 문서
- **수치는 스탯 문서만** 가집니다.
- `👿 몬스터`, `⚔️ 스킬`, `⚡ 속성`, `✨ 액티브 스킬`에는 동작 설명만 남기고, 수치 자리에는 스탯 문서로 가는 링크를 둡니다.
	- 예: `⚔️ 스킬#3-1. 탄환`의 `### Scriptable Object` 목록 → `- 수치는 [[📊 스킬 스탯#3-1. 탄환]]을 따릅니다.`
	- 예: `⚡ 속성#3-3. 노랑(감전)`의 "적의 공격 속도는 기본 5% + 속성 대미지 100당 5%를 둔화합니다." → "적의 공격 속도를 둔화합니다. 수치는 `[[📊 속성 스탯#3-3. 노랑(감전)]]`을 따릅니다."
- 옮긴 원문은 원래 문서의 `# 변경 이력`에 "어디로 옮겼는지"와 함께 남깁니다.

## 2-3. 표 형식
- 테스트 중 훑어보기 좋도록 **표 한 줄 = 스탯 하나**로 씁니다.

| 열 | 내용 |
| --- | --- |
| 스탯 | 스탯 이름 |
| 기획 값 | 기획 문서의 값. 정해지지 않았으면 "미정" |
| 단위 | 초, 배, %, 칸 등 |
| 에셋 · 필드 | Unity에서 값을 고치는 곳 ([[#5. 에셋 · 필드 열]] 참고, 둘지는 결정 대기) |
| 비고 | 수식, 적용 방식(합·곱), 출처 문서 링크 |

- 종류별 개별 스탯은 **행 = 스탯, 열 = 종류**인 비교 표로 씁니다. 예:

| 스탯 | 원형 | 삼각형 | 사각형 | 오각형 |
| --- | --- | --- | --- | --- |
| 고정 HP | – | 1.0 | 1.0 | 20.0 |
| HP 배율 | 1.2 | 1.0 | 3.0 | 5.0 |
| … | | | | |

- 수식이 있는 스탯은 기존처럼 수식 콜아웃을 표 아래 상세 절에 둡니다.
- 문서 맨 위의 요약 표는 두지 않습니다.

# 3. 문서별 상세
## 3-1. 📊 몬스터 스탯
- `# 1. 기획 의도`: 몬스터 수치를 한곳에서 조절하기 위한 문서.
- `# 2. 공유 스탯`: 모든 몬스터 종류에 같은 값이 적용되는 스탯입니다.

| 스탯 | 기획 값 | 출처 |
| --- | --- | --- |
| 스탯 계산 레벨 | 현재 라운드 누적 수 (1-10 → 10, 2-1 → 11) | `👿 몬스터#3-1` |
| 소수점 처리 | 버림 | `👿 몬스터#2` |
| 근접 공격 쿨타임 | 미정 (적용한다고만 되어 있음) | `👿 몬스터#3-2` |
| 오각형 최대 등장 수 | 스테이지당 5 | `👿 몬스터#2` |
| 사망 파티클 지속 시간 | 1초 | `👿 몬스터#3-3` |
| 라운드 생성 시간 | 100초 | `🏰 스테이지#3` |
- `# 3. 개별 스탯`: 비교 표 하나. 행은 고정 HP, HP 배율, 고정 공격력, 공격력 배율, 방어력, 이동 속도, 블록 드롭, 공격 방식, 이동 방식입니다. 미정인 버프(사각형)·대각선 이동(삼각형) 수치도 행으로 넣고 "미정"으로 둡니다.
- `# 4. 상대 비교`: 지금 `👿 몬스터#2`의 ↑↓ 상대 비교 표를 옮깁니다. 3장의 실제 값과 나란히 있어야 의도대로 조절됐는지 확인할 수 있습니다.
- `👿 몬스터`에 남는 것: 2장 공통 규칙(문장), 3장 생애 주기, 4장 유형별 이동·동작 설명. 수치 표는 링크로 바뀝니다. 헤딩은 그대로라 회의록·용어집 링크는 영향이 없습니다.
- `🏰 스테이지#3`의 "100초"는 동작 설명(100초를 N으로 나눠 생성)과 엮여 있어, 문장은 남기고 값 자리에 링크를 겁니다.

## 3-2. 📊 플레이어 스탯
- `📊 스탯#2. 플레이어 스탯`의 2-1~2-6을 **내용 그대로** 옮깁니다.
- 장 구성: `# 1. 기획 의도` / `# 2. 플레이어 스탯` / `# 변경 이력`. 2장과 절 헤딩(`2-1. HP ★` … `2-6. 무적 시간`)을 그대로 유지하므로, 이 문서로 거는 링크는 파일명만 바뀝니다.
- `📊 스탯#1`의 두 문장("플레이어의 판단에 따라 유동적으로 변할 수 있는 스탯 값을 모아두었습니다.", "블록으로 얻을 수 있는 스탯은 ★로 표시합니다.")은 이 문서와 `📊 스킬 스탯`의 1장에 함께 둡니다. ★ 스탯이 두 문서에 나뉘기 때문입니다.

## 3-3. 📊 스킬 점수
- `📊 스탯#4. 스킬 점수`의 4-1~4-3을 **내용 그대로** 옮깁니다.
- 장 구성: `# 1. 기획 의도` / `# 2. 스킬 점수`(2-1. 탄환, 2-2. 광역 탄환, 2-3. 지원) / `# 변경 이력`.
- 탄환의 확인 필요 콜아웃(회의 안건 링크)과 `📊 스탯` 변경 이력 중 스킬 점수 항목(적용 범위 확정, 헤딩 변경)도 함께 옮깁니다.

## 3-4. 📊 스킬 스탯
- `# 2. 공유 스탯`: `📊 스탯#3`의 3-1~3-6(공격력, 속성 공격력, 대미지 증가, 쿨타임 감소, 스킬 지속 시간 증가, 스킬 범위 증가)을 2-1~2-6으로 옮깁니다. 2장 맨 위에 표 한 장으로 요약하고, 수식 콜아웃은 그 아래 절에 둡니다.
	- 공유 규칙도 이 장에 둡니다: 공격 지대 대미지 간격 1초(`⚔️ 스킬#3-2`), 쿨타임 감소 상위 20개 적용.
- `# 3. 개별 스탯`: `⚔️ 스킬`의 Scriptable Object 수치를 스킬별 절로 옮깁니다(3-1. 탄환, 3-2. 광역 탄환, 3-3. 지형(보류), 3-4. 지원). 공통 항목(재사용 대기 시간, 이동 속도)은 비교 표로 한 번에 보여주고, 스킬 고유 항목은 각 절에 둡니다.
- `📊 스탯` 변경 이력 중 폐기된 디버프 스탯(3-7 디버프 시간 증가, 3-8 디버프 중첩)은 이 문서의 변경 이력으로 옮깁니다.
- `⚔️ 스킬`에 남는 것: 모티브, 상세 동작, 타격 우선순위. `### Scriptable Object` 절은 링크 한 줄로 바뀝니다.

## 3-5. 📊 속성 스탯
- `# 2. 공유 스탯`: 모든 속성에 같은 규칙으로 적용되는 값입니다.

| 스탯 | 기획 값 | 출처 |
| --- | --- | --- |
| 지속 대미지 간격 | 1초 (감전·독 "1초 마다") | `⚡ 속성#3-3`, `#3-6` |
| 수치 계산 기준 | 속성 대미지 100당 증가 | `⚡ 속성#3-3`~`#3-5` |
- `# 3. 개별 스탯`: 속성별 절(3-1. 빨강(폭발) … 3-7. 회색(넉백)). `⚡ 속성`과 같은 헤딩을 써서 두 문서를 오가기 쉽게 합니다.

| 속성 | 옮길 수치 |
| --- | --- |
| 빨강(폭발) | 폭발 대미지 = 속성 대미지, 폭발 범위(미정) |
| 주황(강화) | 대미지 = 현재 주입된 속성 대미지 + 주황 속성 대미지, 노랑·초록·파랑 효과 최대 1회 중첩, 보라 독 최대 5회 중첩, 회색 넉백 1.5배 |
| 노랑(감전) | 감전 대미지 초당 속성 대미지의 5%, 공격 속도 둔화 기본 5% + 100당 5%, 최대 40%, 예시(150 → 10%) |
| 초록(둔화) | 이동 속도 둔화 기본 10% + 100당 5%, 최대 40%, 예시(150 → 15%) |
| 파랑(방어력 감소) | 방어력 감소 기본 10% + 100당 10%, 최대 100%, 속성을 잃은 뒤 5초 지속 |
| 보라(독) | 독 대미지 초당 속성 대미지의 10%, 최대 5회 중첩 |
| 회색(넉백) | 넉백 거리 = 1초 이동 거리의 3배 |
- 색상 코드(`FFDDDD` 등)는 조절하는 스탯이 아니라 속성의 정의라서 `⚡ 속성`에 남깁니다.
- `⚡ 속성`에 남는 것: 1~2장 전체, 3장의 색상·효과 설명 문장. 수치가 들어 있던 문장은 효과만 남기고 수치 자리에 `[[📊 속성 스탯#3-N. …]]` 링크를 겁니다. 3장 헤딩은 그대로라 회의록 링크(`#3-1. 빨강(폭발)`, `#3-7. 회색(넉백)`)는 영향이 없습니다.

## 3-6. 📊 액티브 스킬 스탯

# 5. 에셋 · 필드 열
## 5-1. 에셋이란
- **에셋**은 Unity 프로젝트 안에 저장된 데이터 파일입니다. 이 프로젝트에서는 게임이 쓰는 수치를 `ProjectP/Assets/Data` 폴더의 `.asset` 파일에 저장합니다.
	- 예: `Bullet_Element.asset`에는 속성 탄환의 재사용 대기 시간 1.5, 이동 속도 5, 공격력 10이 들어 있습니다. 게임은 이 파일의 값을 읽어 탄환을 쏩니다.
- 테스트 중 값을 바꾸려면 Unity 에디터의 Project 창에서 이 파일을 클릭하고, 오른쪽 Inspector 창에서 숫자를 고칩니다. 코드는 건드리지 않습니다.
- **필드**는 그 파일 안의 항목 하나입니다. Inspector에는 영어 이름이 띄어쓰기된 형태로 보입니다.
	- 예: `EnemyData 2.asset`(삼각형 몬스터) 안의 `hpMultiplier` 필드 → Inspector에는 "체력" 묶음 아래 **Hp Multiplier**로 보이고, 마우스를 올리면 "HP 배율. 레벨마다 이 값만큼 체력이 늘어납니다."라는 설명이 뜹니다.

| 에셋 파일 | 담고 있는 수치 | 관련 스탯 문서 |
| --- | --- | --- |

## 5-3. 선택지
| 선택지 | 표에 적는 것 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 위치만 적기 | `EnemyData 2.asset` · `hpMultiplier` | 문서를 보고 Unity에서 고칠 곳을 바로 찾음. 값은 기획 값 하나만 있어 어긋날 일이 없음 | 테스트 중 바꾼 실제 값은 문서에 안 보임 |
| B. 위치 + 현재 값 | 위 내용 + 에셋에 들어 있는 값 | 기획 값과 실제 값을 나란히 비교 | 에셋 값을 바꿀 때마다 문서도 고쳐야 하고, 안 고치면 금방 틀린 값이 됨 |
| C. 적지 않기 | – | 기획 문서가 Unity 구조와 분리됨 | 문서에서 Unity의 어느 파일을 고쳐야 하는지 알 수 없음 |
