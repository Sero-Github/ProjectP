# 2. 정리 원칙
1. **내용 삭제 금지**: 폐기된 사양은 지우지 않고 문서 하단 `# 변경 이력`으로 옮깁니다. 옮길 때 결정 출처(회의록 또는 결정일)를 함께 남깁니다.
2. **규칙마다 소유 문서는 하나**: 규칙의 전문은 한 문서에만 쓰고, 다른 문서에는 한 줄 요약과 링크만 둡니다. 소유 문서는 [[#4. 규칙 소유 문서]]에 정합니다.
3. **미정 사항도 출처는 하나**: 각 문서 안의 콜아웃이 원본이고, `🚧 작업 예정`과 `🏠 Home`은 query로 모아 보는 화면입니다.
4. **헤딩을 고치면 같은 커밋에서 링크를 다시 설정합니다**: 헤딩 번호는 유지하고, 번호나 이름이 바뀌면 그 헤딩을 가리키는 링크를 모두 고친 뒤 링크 검사로 확인합니다.
5. **파일명은 바꾸지 않습니다**: 이모지를 포함해 지금 파일명을 유지합니다. 폴더 이동은 링크에 영향이 없습니다(파일명이 고유하므로).
6. **기계적 변경과 기획 내용 변경은 커밋을 나눕니다.**

- **`📦 가방`, `🎒 인벤토리`, `💎 큐브`를 블록 쪽에 둔 이유**: 세 문서 모두 블록을 보관·배치하거나 블록을 분해해 얻은 재화를 다룹니다. 능력 계산은 스탯·스킬 문서에 있습니다.
- **`✨ 액티브 스킬`을 능력 쪽에 둔 이유**: 액티브 블록의 획득·분해 규칙은 블록 쪽 문서에 맡기고, 이 문서는 회복·폭탄 효과를 정의하는 문서로 둡니다.
- **`50` 번호를 비워 둔 이유**: `UXUI/`를 이번에 제외했기 때문입니다. 나중에 `50 UXUI/`로 옮길 자리로 남겨 둡니다.
- **`💬 시스템 메시지`를 데이터 쪽에 둔 이유**: 로케일 키와 문구 목록이라 CSV 사양과 성격이 같고, UXUI 폴더는 이번에 건드리지 않습니다.
- 지금의 `⚔️ 스킬/` 폴더는 같은 이름의 `⚔️ 스킬.md`와 겹치고, 문서 2~3개뿐인 하위 폴더라 없앱니다.

# 5. 형식 표준
## 5-1. 시스템 문서 템플릿
````markdown
---
status: 확정          # 확정 | 초안 | 작성 예정
category: 블록        # 진행 | 블록 | 능력
updated: 2026-11-19
decided-in: ["[[2026-11-18]]"]
---
```table-of-contents
```
---
# 1. 기획 의도
# 2. 정의
# 3~N. 규칙 / 상세
# N+1. UI/UX          ← 있으면 본문의 마지막 장
# 참고. …             ← 부록은 본문 뒤
# 변경 이력           ← 폐기된 사양 보관소
````
- `properties`·`bases` 코어 플러그인이 이미 켜져 있어, frontmatter만 넣으면 `🏠 Home`에 Bases 표로 문서별 상태와 수정일을 띄울 수 있습니다.

## 5-2. 헤딩
- 장은 `# N.`, 절은 `## N-M.`로 통일하고, **번호는 유지합니다.**
- 헤딩 번호나 이름이 바뀌면 같은 커밋에서 그 헤딩을 가리키는 링크를 모두 다시 설정합니다. 이번 재구성에서 생기는 변경은 [[#7-2. 링크 재설정 목록]]에 정리했습니다.
- 고칠 곳:
	- `🏰 스테이지`, `👿 몬스터`, `📊 스탯`: `1. 문서 개요` → `1. 기획 의도` (이 헤딩으로 거는 링크 없음)
	- `⚡ 속성`: `### 3-1.` → `## 3-1.` (텍스트가 같아 링크 영향 없음)
	- `📊 스탯`: `# 4. [[⚔️ 스킬]] 점수` → `# 4. 스킬 점수`(링크는 본문 첫 줄로), `4-4. 지원` → `4-3. 지원` (거는 링크 없음)
	- `⚔️ 스킬`: `3-3. 지형(보류)` → `3-3. 지형` + 보류 콜아웃 (거는 링크 없음)
	- `🧱 블록 병합`: `참고.` 장을 7장 뒤로 이동 (거는 링크 없음)
	- `📦 가방`의 `4.1.`/`4.2.` 표기는 인벤토리 분리([[#3-3. 문서 분리]])로 없어집니다.

## 5-3. 상태 표시 (7가지 → 4가지)
| 상황 | 표기 | 지금 쓰는 방식 |
| --- | --- | --- |
| 아직 작성 안 됨 | `> [!TODO] 작성 예정: …` | `<span class="will-work">`, "…는 정해지지 않았습니다" |
| 결정됐지만 확인 필요 | `> [!QUESTION] 확인 필요: … (회의 기록 B에만 있음)` | "회의 기록 중 한 쪽(B)에만 적혀 있어…", "유지할지 확인이 필요합니다" |
| 보류 (나중에 다시 볼 사양) | 본문 유지 + `> [!NOTE] 보류: 이유` | `(보류)`, `> [!WARNING] 실제 적용되지 않을 스탯` |
| 폐기 | `# 변경 이력`으로 이동 | `~~취소선~~` |
- 콜아웃은 목록 안에 들여 쓰지 않고, 해당 목록이 끝난 바로 뒤에 둡니다.
- 회의 안건으로 넘긴 항목은 `[!QUESTION]` 콜아웃에 안건 링크를 함께 둡니다. 예: `📊 스탯#4-1`의 확인 필요 문장 → `> [!QUESTION] 확인 필요: … → [[회의 안건#1. 탄환 개수 증가 보너스]]`.
- `# 변경 이력`으로 옮길 대상: `📊 스탯` 3-7·3-8(취소선), `👿 몬스터#3-3`의 회복 아이템·100골드(취소선 3줄), 그리고 [[#7-3. 기획 판단 반영 목록]]에서 바뀌는 옛 문장.
	- `📊 스탯` 3-7·3-8은 문서 끝에 있는 절이라 빼도 다른 번호가 밀리지 않습니다.
- 보류 콜아웃으로 바꿀 대상: `📊 스탯#2-4. 방어력 (% 적용)`, `⚔️ 스킬#3-3. 지형`. 둘 다 본문에 남겨 번호가 바뀌지 않습니다.
- 문서 맨 위의 초안 안내(`✨ 액티브 스킬`)는 frontmatter `status: 초안`으로 대신합니다.
- `custom.css`의 `.will-work`는 전환이 끝나면 지웁니다. 속성 색상 클래스(`.red` 등)는 유지합니다.

## 5-4. 미정 사항 자동 수집
- 각 문서의 `[!TODO]`, `[!QUESTION]` 콜아웃이 원본입니다. 둘 다 Obsidian 기본 콜아웃 종류라 아이콘과 색이 따로 붙습니다.
- `🚧 작업 예정`과 `🏠 Home`에 아래 검색 임베드를 넣습니다. 템플릿과 이 계획 문서는 검색에서 뺍니다.
````markdown
## 작성 예정
```query
"[!TODO]" -path:_Templates -file:"문서 재구성 계획"
```
## 확인 필요
```query
"[!QUESTION]" -path:_Templates -file:"문서 재구성 계획"
```
````
- 전환 순서:
	1. 각 문서의 `<span class="will-work">`와 "정해지지 않았습니다" 문장을 콜아웃으로 바꿉니다(19개 + α).
	2. `🚧 작업 예정`의 "2026-11-18 회의 이후 미정 사항" 목록을 한 줄씩 대조합니다. 문서에 콜아웃이 없는 항목은 해당 문서에 콜아웃으로 추가합니다. 예: "블록 점수 보이기 옵션" → `🧱 블록#6. 외형`, "탄환 속도 조절" → `⚔️ 스킬#3-1. 탄환`.
		- 2026-11-19 결정으로 해결된 항목은 콜아웃을 만들지 않습니다. 예: "타격 우선순위가 다른 스킬 블록끼리 병합 가능 여부" → 병합 조건 변경으로 해결([[#7-3. 기획 판단 반영 목록]] 4번).
	3. 대조가 끝나면 수동 목록을 query 두 개로 바꿉니다. query 결과가 문서별로 묶여 나오므로 목록의 분류(문서 작성 / 블록·큐브 / 드롭·해금 …)는 따로 두지 않습니다.
- `🚧 작업 예정`의 나머지 구성:
	- **게임의 방향성**: 유지합니다.
	- **완료**: `# 완료` 장을 새로 만들고, 그 아래에 `## 누락된 사항(플레이에는 당장 지장이 없는)`과 `## 차기 버전 목표`를 **헤딩 텍스트를 그대로 둔 채** H2로 내립니다. 회의록이 이 두 헤딩으로 링크 6개를 걸고 있는데, Obsidian은 헤딩 레벨이 아니라 텍스트로 찾기 때문에 링크가 유지됩니다.
	- 차기 6번처럼 일부만 결정된 항목은, 결정된 부분은 그대로 두고 미정 부분만 2번 단계에서 문서 콜아웃으로 옮깁니다.
	- 차기 4번(정사각형 해상도 취소, UI 시안 되돌리기)은 pptm 작업이라 이번 재구성에서 건드리지 않고 그대로 둡니다.
	- **생각 중**: 유지합니다. 회의 안건 링크는 2026-11-19에 추가했습니다.

## 5-5. 회의록
- 지금 형식(안건 표 → 회의 결과 → 안건 외 결정)을 그대로 템플릿으로 만듭니다.
- 머리말에 **(A)/(B) 범례**를 둡니다. 시스템 문서에서 "기록자 B에만 있음"을 확인 필요 사유로 쓰고 있기 때문입니다.
- 회의 결과 항목마다 **반영 위치**를 붙입니다. 예: `- #12 회색 속성 추가 사양 → 삭제 ✅ [[⚡ 속성#3-7. 회색(넉백)]]`.
- 결정 뒤에는 회의록 본문을 수정하지 않습니다. 링크 재설정만 예외입니다.
- `회의 안건`은 다음 회의 전까지 안건을 모으는 문서입니다. 회의를 하면 안건을 그 날짜의 회의록으로 옮기고, `회의 안건`에서는 결정된 회의록으로 링크합니다.
- 2026-11-18 회의록의 안건 외 결정 "블록 병합은 같은 속성·같은 스킬의 블록끼리만 가능"은 2026-11-19 결정으로 바뀌었습니다. 회의록 본문은 그대로 두고, `🧱 블록 병합#변경 이력`에 변경 사실을 남깁니다.
